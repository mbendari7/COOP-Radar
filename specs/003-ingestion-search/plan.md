# Implementation Plan: Real Postings Ingestion & Semantic Search

**Branch**: `003-ingestion-search` | **Date**: 2026-10-10 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/003-ingestion-search/spec.md`

---

## Summary

Add real posting ingestion to CoopRadar via scheduled RQ workers and configurable source adapters (JSON API, RSS, CSV upload, manual entry). Every posting gets a pgvector embedding for semantic search, stored in a separate `posting_embeddings` table with an HNSW index. An admin Sources page surfaces run history and errors. Skills are extracted using a regex/keyword taxonomy with LLM fallback. All ingestion tests use recorded `respx` fixtures — no live network calls.

---

## Technical Context

**Language/Version**: Python 3.12 (backend), TypeScript + React 18 (frontend)

**Primary Dependencies**:
- `rq>=1.16` + `rq-scheduler>=0.13` — background jobs (same Redis as auth sessions)
- `respx>=0.21` — httpx request mocking for tests
- `openai>=1.30` — text-embedding-3-small API (existing httpx dep already present)
- `pgvector>=0.3` — pgvector SQLAlchemy integration
- `python-multipart>=0.0.9` — FastAPI CSV file upload support
- `feedparser>=6.0` — RSS/Atom feed parsing
- Existing: `httpx`, `pandas`, `fastapi`, `sqlalchemy[asyncio]`, `pydantic`, `anthropic` (for skill extraction fallback)

**Storage**: PostgreSQL 16 + pgvector; new tables `ingest_sources`, `ingest_runs`, `skills`, `posting_embeddings`; new columns on `postings` (`source_id`, `source_ref`, `closed_at`, `low_confidence_fields`) and `users` (`is_admin`)

**Testing**: pytest + pytest-asyncio + respx (fixture-based, no live calls)

**Target Platform**: Docker Compose (Linux containers)

**Performance Goals**: Semantic search ≤ 300 ms p95 on 10,000 postings; CSV upload 100 rows ≤ 10 s

**Constraints**: Fixture-only tests (FR-016); no scraping behind login (FR-014); CSV upload ≤ 1,000 rows (FR-008)

**Scale/Scope**: 10,000 postings, ~200 sources, HNSW index m=16 ef_construction=64

## Amendment — 2026-10-10 (post-implementation review)

Changes made after this plan was implemented. The decisions above are kept as the original record.

- **Runner order bug fixed**: the source_ref update check now runs *before* fuzzy dedup. Previously a re-run
  treated its own postings as duplicates, never counted them as seen, and then closed all of them.
- **"Run now" no longer leaves a stuck run**: the worker reuses the `IngestRun` row created by the trigger (`run_id`).
- **Embeddings are actually generated**: new postings (ingest, CSV, manual) enqueue `run_embed_job`;
  `python -m app.ingest.embed` backfills everything else (seed data included).
- **Scheduling**: `rq-scheduler` was never started; replaced by a small scheduler thread in `app/worker.py`
  (`INGEST_INTERVAL_HOURS`, default 6) that re-reads enabled sources every 10 minutes.
- **Extraction** is now wired into the runner for fields a feed doesn't provide, and uses `FAST_MODEL`
  (default `claude-haiku-5-5`) instead of a hard-coded `claude-haiku-4-5` ID.
- **Migration 0001**: the generated `search_vector` column used `array_to_string()` (STABLE, rejected in generated
  columns); it now uses the IMMUTABLE wrapper `coopradar_skills_text()`.
- **SQL safety**: the skills filter interpolated user input into SQL; it now uses a bound `ARRAY @>` parameter.
