# Implementation Plan: Accounts & Application Tracker

**Branch**: `002-accounts-tracker` | **Date**: 2026-10-10 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `/specs/002-accounts-tracker/spec.md`

## Summary

Add user accounts (register/login/logout), HTTP-only cookie sessions stored in Redis,
and a saved-postings tracker with per-posting application status (applied / interviewing
/ offer / rejected). Builds on the Feature 001 stack — same FastAPI + SQLAlchemy async
+ PostgreSQL + Redis + React setup — with two new tables (`users`, `saved_postings`),
two new routers (`/api/auth`, `/api/saved`, `/api/me`), and new frontend components
(AuthModal, BookmarkButton, StatusBadge, SavedPostingsPage, auth header slot).

## Technical Context

**Language/Version**: Python 3.12 (backend), TypeScript 5.x (frontend)

**Primary Dependencies** (new for this feature):
- `argon2-cffi` ≥ 23 — password hashing (argon2id variant, OWASP-recommended)
- `redis[asyncio]` ≥ 5.0 — already in compose stack; adds async sub-package
- `email-validator` ≥ 2.0 — already pulled in by Pydantic `EmailStr`

**Storage**: PostgreSQL 16 (two new tables via Alembic 0002) + Redis (session hashes, no migration)

**Testing**: pytest + pytest-asyncio (backend), Vitest + Testing Library (frontend)

**Target Platform**: Linux container (Docker Compose dev), same as Feature 001

**Project Type**: Full-stack web application

**Performance Goals**: Session lookup (Redis GET) < 5ms; auth endpoints < 200ms p95

**Constraints**:
- All session state server-side — no JWT
- Passwords never logged or returned in any response
- Cookie: `HttpOnly; Secure; SameSite=Lax; Max-Age=604800`
- Email stored lowercase; validated by Pydantic `EmailStr`

**Scale/Scope**: Same as Feature 001 (~500 users for MVP)
